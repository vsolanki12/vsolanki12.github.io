Executive Summary

  • A disposable AWS HostedCluster was created with the PR CPO image and a guest LoadBalancer Service.
  • The test VPC contained both an ELBv2 network load balancer and a classic ELB before teardown.
  • A plain oc delete hostedcluster set a deletion timestamp but did not set hypershift.openshift.io/cleanup-cloud-resources: "true"; the HCP was not marked CVOScaledDown, and the load balancers remained.
  • The supported HyperShift destroy flow set the cleanup annotation, completed cloud-resource cleanup, and reported CloudResourcesDestroyed=True.
  • After supported destroy completed, the NLB, classic ELB, test VPC, and generated cluster IAM resources were gone.
  • The PR runtime path was present: the HCO deployment had the memory-backed cloud-token volume and the CPO pod had a cloud-token-minter sidecar.
  • Final result: the cleanup gate behaved as designed, and the supported teardown path successfully removed the AWS load balancers.
Data handling: kubeconfig contents, passwords, private keys, AWS credentials, pull-secret data, and private endpoint details are excluded. Resource identifiers shown here are limited to disposable test resources and the PR image digest.

Scope and Test Harness

LIVE AWS HOSTEDCLUSTER TEARDOWN VALIDATION

This validation focused on the lifecycle condition described by shouldCleanupCloudResources(hcp): cleanup requires the HostedCluster cleanup annotation and a scaled-down control plane. It covered both an ordinary Kubernetes delete and the supported HyperShift destroy workflow.

The HostedCluster was disposable and used a single arm64 worker. The guest load balancer was created through a Kubernetes Service of type LoadBalancer. The management cluster was restored after testing, and all temporary AWS resources were removed.

The destroy command was run after the plain delete had already placed the HostedCluster into deletion. Therefore, the second scenario is recorded as a supported destroy continuation that directly exercised annotation setting and cleanup completion; it is not claimed as a separate fresh-cluster CLI-only run.

Test Harness Adjustment

The management operator initially attempted to obtain AWS credentials from EC2 instance metadata, but pods could not reach the metadata endpoint. The operator was reinstalled with a local AWS credentials file for the test harness and restarted. The temporary OIDC storage used by the disposable HostedCluster was then made readable by AWS STS for JWKS retrieval.

This was an environment setup correction. It was not a failure of the PR code, and the temporary credentials, OIDC bucket, namespaces, CRDs, HostedCluster resources, VPC, load balancers, and generated IAM roles were removed after testing.
