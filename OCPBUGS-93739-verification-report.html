Root Cause Analysis

CODE ANALYSIS — Two-Part Problem

Part 1: HCCO slow LB teardown path

File: control-plane-operator/hostedclusterconfigoperator/controllers/resources/resources.go

During HC deletion, HCCO calls destroyCloudResources → ensureCloudResourcesDestroyed → ensureServiceLoadBalancersRemoved. This function:

StepActionProblem
1Deletes all Services of type LoadBalancerTriggers async CCM NLB deletion
2Polls until all LB Services are gone~2 minutes waiting for CCM to async-delete 6 NLBs

This is redundant on AWS because DestroyInfra already has DestroyV1ELBs/DestroyV2ELBs that delete NLBs directly via the AWS API by VPC, serving as a reliable backstop.

Part 2: E2E teardown validation gap

File: test/e2e/util/fixture.go

The e2e teardown validation discovers tagged NLBs via the Resource Groups Tagging API, but only logged them without actively deleting them. If the async CCM path was slow, the test timed out waiting.

Fix Applied

COMMIT 1 — Skip LB Service Deletion for AWS in HCCO

File: resources.go — ensureCloudResourcesDestroyed()

Added an early return for AWS platform that skips ensureServiceLoadBalancersRemoved entirely, since DestroyInfra handles NLB cleanup directly.

Diff 
 func (r *reconciler) ensureCloudResourcesDestroyed(ctx context.Context) error {
+   // On AWS, NLBs are cleaned up directly by the infrastructure destroy flow
+   // (DestroyV1ELBs/DestroyV2ELBs) which deletes them by VPC. Skipping the
+   // slow async CCM path avoids a ~2 minute wait during teardown.
+   if r.platformType == hyperv1.AWSPlatform {
+       log.Log.Info("Skipping load balancer Service deletion for AWS; NLBs are cleaned up directly by the infrastructure destroy flow")
+       return nil
+   }
     return r.ensureServiceLoadBalancersRemoved(ctx)
 }

File: resources_test.go — Unit test added

TestDestroyCloudResources_WhenPlatformIsAWS_ItShouldSkipLoadBalancerServiceDeletion — verifies that ensureCloudResourcesDestroyed returns nil without invoking ensureServiceLoadBalancersRemoved when platform is AWS.

COMMIT 2 — Actively Delete Tagged NLBs in E2E Teardown

File: fixture.go — deleteTaggedLoadBalancers()

New function that takes discovered tagged LB ARNs and actively calls DeleteLoadBalancer for each, with terminal vs transient error classification:

Key Code 
type loadBalancerDeleter interface {
    DeleteLoadBalancer(ctx context.Context, params *elbv2.DeleteLoadBalancerInput,
        optFns ...func(*elbv2.Options)) (*elbv2.DeleteLoadBalancerOutput, error)
}

func deleteTaggedLoadBalancers(ctx context.Context, t *testing.T,
    client loadBalancerDeleter, mappings []resourcegroupstaggingapitypes.ResourceTagMapping) error {
    for _, m := range mappings {
        // ... filter to ELB ARNs, call DeleteLoadBalancer ...
        if err != nil {
            var opNotPermitted *elbv2types.OperationNotPermittedException
            var resourceInUse *elbv2types.ResourceInUseException
            if errors.As(err, &opNotPermitted) || errors.As(err, &resourceInUse) {
                return fmt.Errorf("terminal error deleting load balancer %s: %w", lbARN, err)
            }
            t.Logf("Failed to delete load balancer %s (will retry): %v", lbARN, err)
        }
    }
    return nil
}
